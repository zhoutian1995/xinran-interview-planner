# 实时研究协议

## 是否使用浏览器

当任务涉及“近期、最新、热点、现在是否适合采访”或用户只提供嘉宾姓名时，主动使用当前环境可用的搜索、浏览器、新闻或公开资料工具。不要先要求用户整理链接。

优先使用专用搜索/API；需要登录状态、动态页面、社交平台主页或页面正文时再使用浏览器。Skill 不指定某一种浏览器实现，由当前 Agent 选择可用工具。

若环境没有联网或浏览能力：

1. 仍可调用 `topics` 给出长青候选；
2. 明确标注“未完成实时热点核验”；
3. 不把内置话题库发布日期当成当前事实；
4. 给出需要补查的查询式和来源清单。

## 研究顺序

1. 身份消歧：姓名、平台、机构、城市和主页至少两个线索吻合。
2. 人物一手资料：本人主页、完整采访、演讲、作品、公司或机构页面。
3. 近期动态：近 7 天、30 天、90 天分层检索。
4. 观众问题：确认热点对应普通人的具体选择，而非只记录热搜名词。
5. 交叉核验：关键事实至少一个一手来源；争议或商业数字尽量两个独立来源。
6. 话题匹配：先找嘉宾最有冲突、最有结果的一段真实经历，再匹配话题库。

## 来源记录

每条来源写入研究包：

```json
{
  "title": "来源标题",
  "url": "https://...",
  "published_at": "YYYY-MM-DD",
  "accessed_at": "YYYY-MM-DD"
}
```

搜索摘要只作为线索，尽量打开原始页面。无法打开原文时标为待核实。

## 最低研究量

- 身份来源至少 2 条。
- 近期热点来源至少 3 条，覆盖两个不同来源。
- 嘉宾一手表达至少 2 条。
- 每个主选题至少有一条嘉宾相关证据和一条当下性证据。

研究完成后再输出结论，不单独倾倒搜索结果。
